# GAS 側のセットアップ

APIキーの発行は不要。Google のクレデンシャルは一切扱わない。スクリプトはスプレッドシートの
所有者自身の権限で動くので、シートへの書き込み許可は初回の認可ダイアログだけで済む。

用意するものは2つだけ。

| もの | 発行場所 | アプリ側の入力欄 |
|---|---|---|
| ウェブアプリの `/exec` URL | 下記手順4で発行される | GASウェブアプリのURL |
| 合言葉 | 自分で決める | 合言葉 |

既存の家計簿スプレッドシートに書き込む。新しくシートは作らず、ヘッダー行にも触らない。

## スクリプトの作り方は2通り

どちらでも動く。**スタンドアロンで作ってしまった場合に作り直す必要はない。**

| | 作り方 | スプレッドシートの指定 |
|---|---|---|
| 紐づき（bound） | スプレッドシートを開いて **拡張機能 → Apps Script** | 不要。`getActiveSpreadsheet()` で取れる |
| スタンドアロン | script.google.com から新規プロジェクト | `SPREADSHEET_ID` プロパティで指定 |

**紐づきは後付けできない。** スタンドアロンのスクリプトを後からスプレッドシートに
紐づける操作は Apps Script に存在しない。スタンドアロンのまま `SPREADSHEET_ID` を
設定して使う（機能上の差はない）。

「拡張機能 → Apps Script」が出てこない場合は、ファイルが Google スプレッドシート形式に
なっていない可能性がある（Excel の `.xlsx` を Drive に置いただけの状態では Apps Script が
使えない）。その場合は **ファイル → Google スプレッドシートとして保存** で変換するか、
スタンドアロン + `SPREADSHEET_ID` で進める。

## 手順

1. スクリプトを用意する（上記のどちらでもよい）
2. エディタの中身を [Code.gs](./Code.gs) の内容で置き換えて保存
3. **プロジェクトの設定（歯車）→ スクリプト プロパティ** で以下を登録

   | プロパティ | 値 | 必須 |
   |---|---|---|
   | `PASSPHRASE` | 自分で決めた合言葉 | 必須 |
   | `SPREADSHEET_ID` | スプレッドシートのID | スタンドアロンの場合は必須 |
   | `SHEET_NAME` | 追記先の**タブ名**（ファイル名ではない） | 任意。未設定なら先頭のタブ |

   合言葉はスクリプト本文に書かない。リポジトリが Public なので、本文に書くと公開される。
   IDもプロパティに置く。

   スプレッドシートのIDはURLから取る。

   ```
   https://docs.google.com/spreadsheets/d/1AbCdEfGhIjKlMnOpQrStUvWxYz/edit#gid=0
                                          ~~~~~~~~~~~~~~~~~~~~~~~~~~~~ ここ
   ```

   家計簿が月ごとのタブに分かれている場合は `SHEET_NAME` を指定する。
4. **デプロイ → 新しいデプロイ → 種類: ウェブアプリ**

   ```
   次のユーザーとして実行: 自分
   アクセスできるユーザー: 全員
   ```

   「全員」が必要。PWA は Google にログインせずに叩くため。ここを「自分のみ」にすると
   アプリからは書き込めない。
5. 初回は認可ダイアログが出る。「詳細」→「安全ではないページに移動」→ 許可する
   （自分が書いたスクリプトに自分のシートへの権限を与えるだけ）
6. 発行された `https://script.google.com/macros/s/.../exec` をコピーし、アプリの設定画面の
   「GASウェブアプリのURL」に貼る。合言葉も同じ値を入れる

## 書き込み先の決め方（重要）

**行の挿入はしない。** シートには整形済みの行（C・D列のドロップダウン、H〜J列の検索キーの
数式）が下方にあらかじめ用意されている。そこを上書きしていく。

**`appendRow` は使えない。** H〜J列に数式が下まで入っているため `getLastRow()` が実データより
遥か下を指し、整形済み範囲の外に書き込んでしまう。

なので **A列（日付）が空いている最初の行**を探して、そこに書く（`firstEmptyRowByColumnA`）。
データの終わりはA列だけで判断する。

書き込むのは **A〜F の6列だけ**。G列以降には触らないので、検索キーの数式はそのまま残り、
書き込んだ日付に応じて再計算される。

A列に空き行が無い場合はエラーを返して何も書かない。その場合はシート側で整形済みの行を
足す（下の行をコピーして貼り付ける）。

## 列の割り当て

| 列 | 内容 | アプリから渡る値 | 型 |
|---|---|---|---|
| A | 日付 | `body.date` | Date（`YYYY-MM-DD` から組み立てる） |
| B | 金額 | `body.total` | 数値 |
| C | 費目 | `body.category` | 食費 / 日用品 / 特別費 |
| D | 小項目 | `body.subCategory` | 食費のときだけ 内食 / 中食 / 外食。他は空文字 |
| E | 支払先 | `body.store` | 文字列 |
| F | 備考 | `body.top5` | `ｻｹ 798円, ﾌﾞﾀﾊﾞﾗ 682円, …` |

費目と小項目は確認画面のドロップダウンで選ぶ。選択肢は `src/lib/categories.ts` にあるので、
シート側の入力規則を増やしたときはそこも合わせる。

並びを変えたい場合は `Code.gs` の `buildRow` を書き換える。列を飛ばしたい場合は `''` を
挟むが、**すでに値が入っている列を空文字で上書きしないよう注意**（整形済み行を再利用する
方式なので、書いた分だけ上書きされる）。列数を変えるときは `COLUMN_COUNT` も直す。

## セキュリティ

`/exec` URL を知っている相手は誰でも POST できるので、URL自体が実質的な秘密情報になる。
その上で合言葉を検証している。URLが漏れた場合は、デプロイを作り直せば古いURLは無効になる。

## 動作確認

デプロイ後、`/exec` をブラウザで開いて `{"ok":true}` が返れば公開設定は正しい。
`doGet` は情報を返さないので、これ自体は漏洩にならない。

## 更新のしかた

`Code.gs` を直したら、**デプロイ → デプロイを管理 → 編集（鉛筆）→ バージョン: 新バージョン
→ デプロイ**。「新しいデプロイ」を選ぶとURLが変わってしまい、アプリ側の再設定が必要になる。
